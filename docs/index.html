embcache

cache your embeddings so you stop paying for the same text twice.

why i made this

I kept re-embedding the same chunks over and over. Every test run, every reindex, every time I reran a notebook. Same text, same vector, new API bill. That's dumb, so I wrote a cache for it.

There are other embedding caches out there. The thing I cared about was actually seeing what it saved, so embcache keeps track of calls skipped, tokens, dollars, and time, and prints it out for you.

what it does

You wrap your embed function and that's basically it:

from embcache import EmbeddingCache

cache = EmbeddingCache(model="text-embedding-3-small")

@cache.wrap
def embed(text):
    return client.embeddings.create(
        input=text, model="text-embedding-3-small"
    ).data[0].embedding

embed("the cat sat")   # miss, hits the API
embed("the cat sat")   # hit, instant + free

print(cache.report())

Under the hood:

  • text gets normalized (whitespace cleaned up, lowercasing if you want it)
  • key is sha256(text + ":" + model), so switching models never gives you a stale vector
  • vectors are stored as packed float32, not JSON, so it's 4 bytes a number
  • backends: SQLite (default), Redis (shared across processes), or in-memory
  • sync and async both work, and batch calls only send the misses
  • savings stick around across runs, so you get a lifetime number, not just this run
  • small CLI: embcache report, info, clear

On a test suite that embeds ~1,500 chunks a run where most of them are repeats:

withoutwith
API calls1,500260
tokens billed~375k~65k
cost per run$0.0075$0.0013

Tiny per run on the cheap model, sure. But it adds up across every CI run and every reindex, and it's 6.5x worse on text-embedding-3-large.

One thing it won't do: semantic matching. "Similar" text never reuses a vector, because that can quietly give you the wrong one. Exact text in, exact vector out.

install

pip install embcache
pip install "embcache[redis]"      # redis backend
pip install "embcache[tiktoken]"   # exact token counts

where it's at / what's next

  • v0.3 async, tiktoken token counts, in-memory backend
